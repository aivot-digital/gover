# Grundbegriffe in Prosuna

## Abläufe gestalten und Vorgänge bearbeiten

| Begriff | Bedeutung |
| --- | --- |
| <a id="prosuna"></a>Prosuna | Plattform, mit der [Organisationen](#organisation) digitale Abläufe gestalten und ausführen. Dazu gehören die Erfassung von Angaben in [Formularen](#formular), die Bearbeitung von [Vorgängen](#vorgang) sowie die Zusammenarbeit von [Mitarbeiter:innen](#mitarbeiterin) und externen [Beteiligten](#beteiligte). Manuelle Arbeit und automatisierte Verarbeitung können dabei in einem [Prozess](#prozess) zusammenwirken. |
| <a id="instanz"></a>Instanz | Eine einzelne betriebene Installation von [Prosuna](#prosuna) mit eigenen Daten, Einstellungen und [Anbindungen](#anbindung). |
| <a id="modul"></a>Modul | Abgrenzbarer Funktionsbereich von [Prosuna](#prosuna), der für eine [Instanz](#instanz) aktiviert wird, etwa „[Formulare](#formular)“ oder „[Prozesse](#prozess)“. Der Modulzuschnitt bestimmt, welche Funktionen grundsätzlich zur Verfügung stehen. Die Systeminformationen zeigen unter „Funktionsumfang“ die aktivierten Module und gegebenenfalls geltende Grenzen. Welche freigeschalteten Funktionen eine Person nutzen darf, bestimmen ihre [Berechtigungen](#berechtigung). |
| <a id="prozess"></a>Prozess | Übergeordneter Eintrag für einen wiederverwendbaren Ablauf, zum Beispiel die Bearbeitung von Veranstaltungsanmeldungen. Er bündelt alle [Prozessversionen](#prozessversion) dieses Ablaufs. Wie die Bearbeitung ablaufen soll, beschreibt die [Prozessdefinition](#prozessdefinition); jeder konkrete Durchlauf wird als eigener [Vorgang](#vorgang) geführt. |
| <a id="prozessdefinition"></a>Prozessdefinition | Beschreibung, wie ein Ablauf in [Prosuna](#prosuna) funktionieren soll: welche Schritte ausgeführt werden, welche Informationen sie benötigen und unter welchen Bedingungen es weitergeht. Dazu werden [Prozesselemente](#prozesselement) über [Verbindungen](#verbindung) zu einem **Prozessgraphen** verbunden, der auch Beginn und Ende des Ablaufs abbildet. Ein bestimmter Stand dieser Beschreibung wird in einer [Prozessversion](#prozessversion) eines [Prozesses](#prozess) festgehalten. |
| <a id="prozessversion"></a>Prozessversion | Mit einer Versionsnummer gekennzeichneter Stand einer [Prozessdefinition](#prozessdefinition) innerhalb eines [Prozesses](#prozess). Dazu gehören die konfigurierten [Prozesselemente](#prozesselement), ihre [Verbindungen](#verbindung), [Formulare](#formular), zugehörige [UI-Definitionen](#ui-definition) und Einstellungen. |
| <a id="prozesselement"></a>Prozesselement | Prozesselemente sind die konfigurierbaren Bestandteile, aus denen sich eine [Prozessdefinition](#prozessdefinition) zusammensetzt. Über [Verbindungen](#verbindung) wird festgelegt, welche Elemente aufeinander folgen können. Es gibt vier Kategorien: **Auslöser** für den Start eines [Vorgangs](#vorgang), **Aktion** für Verarbeitungsschritte, **Ablaufsteuerung** für Verzweigungen oder zeitliche Steuerung und **Abschluss** für das Beenden eines [Vorgangs](#vorgang). Die konkrete Ausführung eines Elements wird als [Aufgabe](#aufgabe) geführt. |
| <a id="port"></a>Port | Anschluss eines [Prozesselements](#prozesselement), an dem eine [Verbindung](#verbindung) beginnen oder enden kann. Ein **Eingangsport** ist für eingehende [Verbindungen](#verbindung) bestimmt, ein **Ausgangsport** für ausgehende [Verbindungen](#verbindung). |
| <a id="verbindung"></a>Verbindung | Gerichtete Verknüpfung vom [Ausgangsport](#port) eines [Prozesselements](#prozesselement) zum [Eingangsport](#port) eines anderen [Prozesselements](#prozesselement) derselben [Prozessversion](#prozessversion). Sie legt fest, welcher Schritt über diesen Ausgang als Nächstes erreicht werden kann. Zusammen bilden [Prozesselemente](#prozesselement) und ihre Verbindungen den in der [Prozessdefinition](#prozessdefinition) beschriebenen Ablauf. Ein [Prozesspfad](#prozesspfad) kann über mehrere Verbindungen verlaufen. |
| <a id="prozesspfad"></a>Prozesspfad | Möglicher oder bereits durchlaufener Weg durch den in einer [Prozessdefinition](#prozessdefinition) beschriebenen Ablauf. Er verläuft über [Prozesselemente](#prozesselement) und deren [Verbindungen](#verbindung). Entscheidungen und Bedingungen bestimmen, welche Prozesspfade ein [Vorgang](#vorgang) nehmen kann oder bereits genommen hat. |
| <a id="vorgang"></a>Vorgang | Ein konkreter Durchlauf eines [Prozesses](#prozess), zum Beispiel eine einzelne Veranstaltungsanmeldung. Er wird auf Grundlage einer bestimmten [Prozessversion](#prozessversion) gestartet und besitzt eigene [Vorgangsdaten](#vorgangsdatenebene), [Aufgaben](#aufgabe) und eine [Vorgangskennung](#vorgangskennung). Während der Bearbeitung können mehrere [Übermittlungen](#uebermittlung) und Zahlungen zu demselben Vorgang gehören. |
| <a id="aufgabe"></a>Aufgabe | Konkrete Ausführung eines [Prozesselements](#prozesselement) innerhalb eines [Vorgangs](#vorgang), etwa eine Prüfung, eine Berechnung oder das Anfordern weiterer Angaben. Bei **automatischer Ausführung** erledigt das System den Schritt selbstständig. Bei **manueller Ausführung** bearbeitet eine Person den Schritt oder bestätigt seine Erledigung. Bei **teilautomatisierter Ausführung** werden automatische Verarbeitung und manuelle Bearbeitung kombiniert. Für die interne Bearbeitung gibt es [Mitarbeitendenaufgaben](#mitarbeitendenaufgabe), für die externe Mitwirkung [Aufgaben für Beteiligte](#aufgabe-fuer-beteiligte). |
| <a id="vorgangskennung"></a>Vorgangskennung | Von [Prosuna](#prosuna) vergebene Kennung, die einen [Vorgang](#vorgang) innerhalb einer [Instanz](#instanz) eindeutig identifiziert. Ihre Form wird für die [Prozessversion](#prozessversion) festgelegt und kann beispielsweise eine fortlaufende Nummer oder zufällig erzeugte Bestandteile enthalten. Zusätzlich können externe [Aktenzeichen](#aktenzeichen) hinterlegt werden. |
| <a id="aktenzeichen"></a>Aktenzeichen | In einem anderen System, beispielsweise einem [Fachsystem](#fachsystem), vergebene Kennung, die in [Prosuna](#prosuna) zur zusätzlichen Zuordnung eines [Vorgangs](#vorgang) hinterlegt wird. Ein [Vorgang](#vorgang) kann mehrere Aktenzeichen besitzen. Seine von [Prosuna](#prosuna) vergebene [Vorgangskennung](#vorgangskennung) bleibt davon unabhängig bestehen. |

## Oberflächen gestalten und Angaben übermitteln

| Begriff | Bedeutung |
| --- | --- |
| <a id="ui-definition"></a>UI-Definition | Konfigurierte Beschreibung einer Oberfläche: ihre [Formularelemente](#formularelement), deren Anordnung sowie Anzeige- und Eingaberegeln. Ein [Formular](#formular) besitzt eine UI-Definition. UI-Definitionen beschreiben auch Oberflächen für [Mitarbeitendenaufgaben](#mitarbeitendenaufgabe), die Erfassung von [Datenobjekten](#datenobjekt) und Konfigurationen. |
| <a id="formular"></a>Formular | Fachliches Eingabeangebot für [Beteiligte](#beteiligte) zur Erfassung und [Übermittlung](#uebermittlung) von Angaben für einen neuen oder bestehenden [Vorgang](#vorgang). Die [ausfüllende Person](#ausfuellende-person) nutzt das Formular zur Eingabe; seine [UI-Definition](#ui-definition) beschreibt den Aufbau und die Regeln der Oberfläche. Die [Übermittlung](#uebermittlung) kann einen neuen [Vorgang](#vorgang) starten oder einen bestehenden ergänzen. |
| <a id="formularelement"></a>Formularelement | Wiederverwendbarer Bestandteil einer [UI-Definition](#ui-definition), zum Beispiel ein Textfeld, eine Auswahl, eine Überschrift oder eine Gruppe von Eingaben. Formularelemente werden in [Formularen](#formular) und anderen konfigurierten Oberflächen verwendet, um Angaben zu erfassen oder die Oberfläche zu gliedern und zu erläutern. Die Einstellungen eines Formularelements können beispielsweise Pflichtangaben, erlaubte Werte oder die Sichtbarkeit festlegen. |
| <a id="uebermittlung"></a>Übermittlung | Übergabe der ausgefüllten Angaben und gegebenenfalls beigefügter [Anlagen](#anlage) aus einem [Formular](#formular) an den vorgesehenen Bearbeitungsschritt. Sie kann einen [Vorgang](#vorgang) starten oder angeforderte Ergänzungen zu einem bestehenden Fall liefern. |

## Personen, Zugänge und Bearbeitungsoberflächen

| Begriff | Bedeutung |
| --- | --- |
| <a id="beteiligte"></a>Beteiligte | Personen oder [Organisationen](#organisation), die von außen an einem [Vorgang](#vorgang) mitwirken, etwa Angaben bereitstellen, Ergänzungen liefern oder eine Zahlung ausführen. Sie benötigen dafür kein internes [Konto](#konto) als [Mitarbeiter:in](#mitarbeiterin). Für ihre Mitwirkung stehen die [Ansicht für Beteiligte](#ansicht-fuer-beteiligte) und gegebenenfalls eine [Identität](#identitaet) zur Verfügung. |
| <a id="ausfuellende-person"></a>Ausfüllende Person | Der Mensch, der Angaben in ein [Formular](#formular) eingibt. Diese Person kann für sich selbst, für eine andere Person oder für eine [Organisation](#organisation) handeln. Sie muss deshalb nicht mit der Person oder Einrichtung übereinstimmen, auf die sich die eingegebenen Angaben beziehen. |
| <a id="mitarbeiterin"></a>Mitarbeiter:in | Person mit einem internen [Konto](#konto), die in [Prosuna](#prosuna) Abläufe gestaltet, [Vorgänge](#vorgang) bearbeitet oder die Installation verwaltet. Sie arbeitet in der [Bearbeitungsoberfläche](#bearbeitungsoberflaeche). Welche Handlungen ihr dort möglich sind, bestimmen ihre [Berechtigungen](#berechtigung). |
| <a id="konto"></a>Konto | Persönlicher Anmeldezugang mit zugehörigen Kontoinformationen. [Mitarbeiter:innen](#mitarbeiterin) nutzen ein internes Konto, um sich an der [Bearbeitungsoberfläche](#bearbeitungsoberflaeche) von [Prosuna](#prosuna) anzumelden. [Beteiligte](#beteiligte) können sich mit einem Konto bei einem [Identitätsanbieter](#identitaetsanbieter) anmelden, um eine [Identität](#identitaet) für einen [Vorgang](#vorgang) anzulegen. |
| <a id="identitaet"></a>Identität | Zu einem [Vorgang](#vorgang) gespeicherte Angaben über [Beteiligte](#beteiligte), zum Beispiel der Name einer Person oder [Organisation](#organisation), eine E-Mail-Adresse oder eine Kennung. Darüber lassen sich Nachrichten und [Aufgaben für Beteiligte](#aufgabe-fuer-beteiligte) adressieren. Die Angaben können aus einer Anmeldung über einen [Identitätsanbieter](#identitaetsanbieter) oder, sofern freigegeben, aus einer direkt angegebenen E-Mail-Adresse stammen. Ein internes [Konto](#konto) wird dadurch nicht vorausgesetzt. |
| <a id="bearbeitungsoberflaeche"></a>Bearbeitungsoberfläche | Interner Arbeitsbereich von [Prosuna](#prosuna), in dem [Mitarbeiter:innen](#mitarbeiterin) [Prozesse](#prozess), [Formulare](#formular) und [UI-Definitionen](#ui-definition) gestalten, [Vorgänge](#vorgang) bearbeiten oder Einstellungen verwalten. Der Zugang erfolgt über ein internes [Konto](#konto). Externe [Beteiligte](#beteiligte) erledigen ihre Schritte über die [Ansicht für Beteiligte](#ansicht-fuer-beteiligte). |
| <a id="ansicht-fuer-beteiligte"></a>Ansicht für Beteiligte | Externe Oberfläche, über die [Beteiligte](#beteiligte) die für sie vorgesehenen Informationen zu einem [Vorgang](#vorgang) ansehen und [Aufgaben für Beteiligte](#aufgabe-fuer-beteiligte) erledigen. Der Zugang kann über einen bereitgestellten Link und gegebenenfalls eine [Identität](#identitaet) erfolgen. Ein internes [Konto](#konto) als [Mitarbeiter:in](#mitarbeiterin) ist dafür nicht nötig. |
| <a id="mitarbeitendenaufgabe"></a>Mitarbeitendenaufgabe | [Aufgabe](#aufgabe) innerhalb eines [Vorgangs](#vorgang), die von [Mitarbeiter:innen](#mitarbeiterin) bearbeitet wird, zum Beispiel eine fachliche Prüfung oder Bestätigung. Um die Aufgabe einzusehen und zu bearbeiten, müssen [Mitarbeiter:innen](#mitarbeiterin) mit einem internen [Konto](#konto) an der [Bearbeitungsoberfläche](#bearbeitungsoberflaeche) von [Prosuna](#prosuna) angemeldet sein und die erforderlichen [Berechtigungen](#berechtigung) besitzen. Die zugewiesene [Mitarbeiter:in](#mitarbeiterin) heißt [zuständige Person](#zustaendige-person). Für das Anzeigen und Erfassen von Aufgabendaten kann eine [UI-Definition](#ui-definition) hinterlegt sein. |
| <a id="aufgabe-fuer-beteiligte"></a>Aufgabe für Beteiligte | [Aufgabe](#aufgabe) in einem bestehenden [Vorgang](#vorgang), bei der [Beteiligte](#beteiligte) mitwirken sollen, etwa durch die [Übermittlung](#uebermittlung) angeforderter Angaben über ein [Formular](#formular) oder durch eine Zahlung. Die Bearbeitung findet in der [Ansicht für Beteiligte](#ansicht-fuer-beteiligte) statt. Dafür wird kein internes [Konto](#konto) benötigt. |
| <a id="zustaendige-person"></a>Zuständige Person | Die einem [Vorgang](#vorgang) oder einer [Mitarbeitendenaufgabe](#mitarbeitendenaufgabe) zugewiesene [Mitarbeiter:in](#mitarbeiterin). Die Zuweisung macht erkennbar, wer die interne Bearbeitung übernehmen soll. Bei einer [Aufgabe](#aufgabe) ist die zuständige Person zugleich die bearbeitende Person; eine Vertretung kann die Bearbeitung übernehmen. |

## Organisation und Berechtigungen

| Begriff | Bedeutung |
| --- | --- |
| <a id="organisation"></a>Organisation | Behörde, Unternehmen, Verein oder andere Einrichtung. Eine Organisation kann [Prosuna](#prosuna) für ihre eigenen Abläufe einsetzen oder als [Beteiligte](#beteiligte) an [Vorgängen](#vorgang) mitwirken. Wenn sie [Prosuna](#prosuna) selbst einsetzt, lassen sich ihre interne Struktur durch [Organisationseinheiten](#organisationseinheit) und ihre Zusammenarbeit durch [Teams](#team) abbilden. |
| <a id="organisationseinheit"></a>Organisationseinheit | Teil der internen Struktur einer [Organisation](#organisation), zum Beispiel ein Bereich oder eine Abteilung. Über- und untergeordnete Einheiten bilden deren Hierarchie ab. [Mitarbeiter:innen](#mitarbeiterin) werden über [Mitgliedschaften](#mitgliedschaft) zugeordnet; [Teams](#team) ergänzen diese Struktur für bereichsübergreifende Zusammenarbeit. |
| <a id="team"></a>Team | Gruppe für die Zusammenarbeit innerhalb einer [Organisation](#organisation), insbesondere über die Grenzen einzelner [Organisationseinheiten](#organisationseinheit) hinweg, zum Beispiel ein Projektteam. Die Zugehörigkeit wird über [Mitgliedschaften](#mitgliedschaft) gepflegt. So kann eine Person in ihrer Abteilung und zugleich in einem bereichsübergreifenden Team mitarbeiten. |
| <a id="mitgliedschaft"></a>Mitgliedschaft | Zuordnung einer [Mitarbeiter:in](#mitarbeiterin) zu einer [Organisationseinheit](#organisationseinheit) oder einem [Team](#team). Zu dieser Zuordnung können [Domänenrollen](#domaenenrolle) vergeben werden, aus denen sich [Berechtigungen](#berechtigung) für den jeweiligen Arbeitsbereich ergeben. Eine Person kann mehrere Mitgliedschaften besitzen. |
| <a id="berechtigung"></a>Berechtigung | Erlaubnis, in [Prosuna](#prosuna) eine bestimmte Handlung auszuführen, zum Beispiel einen [Prozess](#prozess) zu lesen oder einen [Vorgang](#vorgang) zu bearbeiten. Die Erlaubnis kann für die gesamte [Instanz](#instanz) oder für einen begrenzten Bereich gelten. Sie wird unter anderem über [Rollen](#rolle) vergeben. |
| <a id="rolle"></a>Rolle | Benannte Zusammenstellung von [Berechtigungen](#berechtigung), die gemeinsam zugewiesen werden, zum Beispiel die Rechte für eine bestimmte Bearbeitungsfunktion. So müssen wiederkehrende Zugriffsrechte nicht einzeln vergeben werden. [Prosuna](#prosuna) unterscheidet [Systemrollen](#systemrolle) und [Domänenrollen](#domaenenrolle) nach dem Bereich, in dem ihre Rechte gelten. |
| <a id="systemrolle"></a>Systemrolle | [Rolle](#rolle), die einem internen [Konto](#konto) zugewiesen wird und [Berechtigungen](#berechtigung) für die gesamte [Instanz](#instanz) gewährt, zum Beispiel das Lesen aller [Prozesse](#prozess). Jede [Mitarbeiter:in](#mitarbeiterin) besitzt genau eine Systemrolle. Diese Rechte gelten unabhängig von den einzelnen [Mitgliedschaften](#mitgliedschaft) in [Organisationseinheiten](#organisationseinheit) oder [Teams](#team). |
| <a id="domaenenrolle"></a>Domänenrolle | [Rolle](#rolle), die einer [Mitarbeiter:in](#mitarbeiterin) über ihre [Mitgliedschaft](#mitgliedschaft) in einer [Organisationseinheit](#organisationseinheit) oder einem [Team](#team) zugewiesen wird. Ihre [Berechtigungen](#berechtigung) wirken im zugehörigen organisatorischen Bereich, etwa an den dort zugänglichen [Prozessen](#prozess) oder [Vorgängen](#vorgang). Dieselbe [Mitarbeiter:in](#mitarbeiterin) kann beispielsweise in [Organisationseinheit](#organisationseinheit) A eine andere [Rolle](#rolle) haben als in [Organisationseinheit](#organisationseinheit) B. |
| <a id="verwaltende-organisationseinheit"></a>Verwaltende Organisationseinheit | [Organisationseinheit](#organisationseinheit), die einen [Prozess](#prozess) verwaltet und für ihn zuständig ist. Jeder [Prozess](#prozess) ist genau einer verwaltenden Organisationseinheit zugeordnet; sie bildet die Grundlage für die prozessbezogenen [Berechtigungen](#berechtigung). Weitere Teams oder Organisationseinheiten lassen sich als [berechtigte Organisationseinheit](#berechtigte-organisationseinheit) oder [berechtigtes Team](#berechtigtes-team) einbeziehen. |
| <a id="berechtigte-organisationseinheit"></a>Berechtigte Organisationseinheit | [Organisationseinheit](#organisationseinheit), die über die „Prozessberechtigungen“ Zugriff auf einen [Prozess](#prozess) erhält, ohne ihn zu verwalten. Sie wird von der [verwaltenden Organisationseinheit](#verwaltende-organisationseinheit) hinzugefügt, um an dem [Prozess](#prozess) mitzuarbeiten, ihn zu prüfen oder andere ihr erlaubte Handlungen daran auszuführen. Der Umfang ergibt sich aus den dort freigegebenen [Berechtigungen](#berechtigung). |
| <a id="berechtigtes-team"></a>Berechtigtes Team | [Team](#team), das über die „Prozessberechtigungen“ Zugriff auf einen [Prozess](#prozess) erhält. Es wird von der [verwaltenden Organisationseinheit](#verwaltende-organisationseinheit) hinzugefügt, um an dem [Prozess](#prozess) mitzuarbeiten, ihn zu prüfen oder andere ihm erlaubte Handlungen daran auszuführen. Der Umfang ergibt sich aus den dort freigegebenen [Berechtigungen](#berechtigung). |
| <a id="beteiligte-organisationseinheit"></a>Beteiligte Organisationseinheit | [Organisationseinheit](#organisationseinheit), die Zugriff auf [Vorgänge](#vorgang) eines [Prozesses](#prozess) erhält, um die aus den [Prozesselementen](#prozesselement) entstehenden [Mitarbeitendenaufgaben](#mitarbeitendenaufgabe) zu bearbeiten. Beteiligt wird sie entweder über die „Standardrechte für neue Vorgänge“ des [Prozesses](#prozess), die bei der Anlage eines [Vorgangs](#vorgang) einmalig übernommen werden, oder indem sie nachträglich zu einem laufenden [Vorgang](#vorgang) hinzugefügt wird. Nachträglich hinzufügen können sie [Mitarbeiter:innen](#mitarbeiterin) mit der [Berechtigung](#berechtigung) „Vorgang bearbeiten“ für diesen [Vorgang](#vorgang). Der Umfang ergibt sich aus den jeweils freigegebenen [Berechtigungen](#berechtigung). Anders als externe [Beteiligte](#beteiligte) arbeitet sie intern in der [Bearbeitungsoberfläche](#bearbeitungsoberflaeche). |
| <a id="beteiligtes-team"></a>Beteiligtes Team | [Team](#team), das Zugriff auf [Vorgänge](#vorgang) eines [Prozesses](#prozess) erhält, um die aus den [Prozesselementen](#prozesselement) entstehenden [Mitarbeitendenaufgaben](#mitarbeitendenaufgabe) zu bearbeiten. Beteiligt wird es entweder über die „Standardrechte für neue Vorgänge“ des [Prozesses](#prozess), die bei der Anlage eines [Vorgangs](#vorgang) einmalig übernommen werden, oder indem es nachträglich zu einem laufenden [Vorgang](#vorgang) hinzugefügt wird. Nachträglich hinzufügen können es [Mitarbeiter:innen](#mitarbeiterin) mit der [Berechtigung](#berechtigung) „Vorgang bearbeiten“ für diesen [Vorgang](#vorgang). Der Umfang ergibt sich aus den jeweils freigegebenen [Berechtigungen](#berechtigung). Anders als externe [Beteiligte](#beteiligte) arbeitet es intern in der [Bearbeitungsoberfläche](#bearbeitungsoberflaeche). |

## Daten verwenden und Regeln gestalten

| Begriff | Bedeutung |
| --- | --- |
| <a id="datenebene"></a>Datenebene | Abgegrenzter Datenbereich bei der Verarbeitung eines [Vorgangs](#vorgang). Datenebenen trennen Informationen nach ihrem Verwendungszweck, etwa fachliche Angaben und technische Arbeitsdaten. |
| <a id="vorgangsdatenebene"></a>Vorgangsdatenebene | [Datenebene](#datenebene), in der die **Vorgangsdaten** als gemeinsamer fachlicher Datenbestand eines [Vorgangs](#vorgang) gehalten werden. Hier werden gezielt Daten hinterlegt, die im weiteren Verlauf regelmäßig benötigt werden oder einfach zugänglich sein sollen, etwa Formularangaben oder Entscheidungen. Ergebniswerte aus der [Elementdatenebene](#elementdatenebene) müssen dafür gezielt übernommen werden. [Aufgaben](#aufgabe) können diese Daten lesen, ergänzen und ändern. Der jeweilige Datenstand wird bei der [Aufgabe](#aufgabe) festgehalten und an das nächste [Prozesselement](#prozesselement) weitergegeben. Der Zugriff in [Variablen](#variable) und [Low-Code-Skripten](#low-code-skript) beginnt mit `$`, zum Beispiel `$.person.name` für den Namen einer Person. |
| <a id="elementdatenebene"></a>Elementdatenebene | [Datenebene](#datenebene) mit den **Elementdaten**, also den bei einer [Aufgabe](#aufgabe) gespeicherten Ergebnissen eines [Prozesselements](#prozesselement). Die Daten bleiben diesem [Prozesselement](#prozesselement) zugeordnet und werden unter seinem **Datenschlüssel** (technischen Namen) bereitgestellt. Werte, die regelmäßig benötigt werden oder einfacher zugänglich sein sollen, werden gezielt zusätzlich in die [Vorgangsdatenebene](#vorgangsdatenebene) übernommen. Der Zugriff in [Variablen](#variable) und [Low-Code-Skripten](#low-code-skript) beginnt mit `_`, zum Beispiel `_.pruefung.ergebnis`. |
| <a id="laufzeitdatenebene"></a>Laufzeitdatenebene | [Datenebene](#datenebene), in der die **Laufzeitdaten** einer einzelnen [Aufgabe](#aufgabe) gehalten werden. Das sind interne Arbeitsdaten, etwa ein gespeicherter Zwischenstand. Das ausführende [Prozesselement](#prozesselement) nutzt und pflegt diese Daten, um seine Verarbeitung auszuführen oder nach einer Unterbrechung fortzusetzen. Für die Weitergabe fachlicher Daten und Ergebnisse an weitere Schritte dienen die [Vorgangsdatenebene](#vorgangsdatenebene) und die [Elementdatenebene](#elementdatenebene). Ein direkter Zugriff auf diese Datenebene über [Variablen](#variable) oder [Low-Code-Skripte](#low-code-skript) steht nicht zur Verfügung. |
| <a id="geschuetzte-vorgangsdatenebene"></a>Geschützte Vorgangsdatenebene | [Datenebene](#datenebene) mit systemseitig bereitgestellten Informationen zu einem [Vorgang](#vorgang), zum Beispiel seiner [Vorgangskennung](#vorgangskennung), seinen [Identitäten](#identitaet) und [Anlagensätzen](#anlagensatz). Diese Angaben werden für die aktuelle Verarbeitung zusammengestellt. Der Zugriff beginnt mit `$$`, zum Beispiel `$$.caseNumber` für die [Vorgangskennung](#vorgangskennung). Angaben zur Ausführung einzelner Schritte stehen im Teilbereich [Elementmetadatenebene](#elementmetadatenebene). |
| <a id="elementmetadatenebene"></a>Elementmetadatenebene | Teilbereich der [geschützten Vorgangsdatenebene](#geschuetzte-vorgangsdatenebene) mit Informationen zur Ausführung der [Prozesselemente](#prozesselement), abgeleitet aus ihren [Aufgaben](#aufgabe). Dazu gehören Start- und Endzeitpunkte, die Laufzeit und die Kennung des zugewiesenen [Kontos](#konto). Der Zugriff beginnt mit `$$.taskMetadata`, zum Beispiel `$$.taskMetadata.pruefung.finished` für den Abschlusszeitpunkt des Elements `pruefung`. Dessen fachliches Ergebnis steht in der [Elementdatenebene](#elementdatenebene). |
| <a id="datenmodell"></a>Datenmodell | Bauplan für zentral gespeicherte, wiederverwendbare [Datenobjekte](#datenobjekt). Er legt fest, welche Angaben ein solcher Eintrag enthalten kann, zum Beispiel Name, Adresse und Öffnungszeiten für Standorte. Eine [UI-Definition](#ui-definition) beschreibt die Oberfläche zur Erfassung dieser Angaben. Der Bauplan beschreibt den Aufbau; ein konkreter Standort mit seinen Angaben ist ein einzelnes [Datenobjekt](#datenobjekt). Der direkte Zugriff erfordert die Anmeldung mit einem internen [Konto](#konto) und die entsprechenden [Berechtigungen](#berechtigung). |
| <a id="datenobjekt"></a>Datenobjekt | Einzelner zentral gespeicherter Eintrag nach dem Aufbau eines [Datenmodells](#datenmodell), zum Beispiel ein bestimmter Standort mit Name und Adresse. Der direkte Zugriff erfordert die Anmeldung mit einem internen [Konto](#konto) und die entsprechenden [Berechtigungen](#berechtigung). [Prozesse](#prozess) können auf diese Einträge zurückgreifen. Gemeinsam benötigte Angaben lassen sich dadurch an einer Stelle pflegen und wiederverwenden. |
| <a id="codeliste"></a>Codeliste | Wiederverwendbare Liste von Auswahlwerten für [Formularelemente](#formularelement), vor allem zum Einsatz in [Formularen](#formular), zum Beispiel Länder oder Veranstaltungsarten. Zu einem Wert kann eine sichtbare Bezeichnung gehören, etwa „Deutschland“ zum Wert „DE“. Die Auswahlwerte sind öffentlich und ohne Anmeldung abrufbar. Die Pflege erfordert die Anmeldung mit einem internen [Konto](#konto) und die entsprechenden [Berechtigungen](#berechtigung). |
| <a id="variable"></a>Variable | Verweis auf einen verfügbaren Wert, statt diesen fest einzutragen, zum Beispiel auf einen Namen aus einem [Formular](#formular) oder einen Betrag aus den [Vorgangsdaten](#vorgangsdatenebene). Bei der Verwendung wird der zum jeweiligen Fall passende Wert eingesetzt. Für die Verarbeitung eines [Vorgangs](#vorgang) können Werte aus unterschiedlichen [Datenebenen](#datenebene) stammen. So können Texte, Berechnungen und [Vorlagen](#vorlage) mit den erfassten Angaben arbeiten. |
| <a id="no-code-ausdruck"></a>No-Code-Ausdruck | Grafisch zusammengestellte Regel oder Berechnung, für die kein eigener Programmcode geschrieben werden muss. Ein Ausdruck kann zum Beispiel Werte vergleichen, einen Betrag berechnen oder bestimmen, ob ein [Formularelement](#formularelement) angezeigt wird. Dabei können [Variablen](#variable) die benötigten Eingabewerte liefern. Für frei programmierten Code steht ein [Low-Code-Skript](#low-code-skript) zur Verfügung. |
| <a id="low-code-skript"></a>Low-Code-Skript | Eigener Programmcode für eine Berechnung oder Verarbeitung in [Prosuna](#prosuna), beispielsweise in JavaScript. Damit lassen sich Regeln umsetzen, die über die vorhandenen Einstellmöglichkeiten hinausgehen. Ein Skript kann etwa [Vorgangsdaten](#vorgangsdatenebene) verarbeiten oder Werte von [Formularelementen](#formularelement) berechnen. Für grafisch zusammengestellte Regeln stehen [No-Code-Ausdrücke](#no-code-ausdruck) zur Verfügung. |

## Dateien und Anbindungen

| Begriff | Bedeutung |
| --- | --- |
| <a id="datei"></a>Datei | Digitaler Inhalt wie ein PDF, ein Bild oder eine Dokumentvorlage. Im Bereich „Dateien und Medien“ können Dateien für die Wiederverwendung in [Formularen](#formular), [Prozessen](#prozess) und [Erscheinungsbildern](#erscheinungsbild) bereitgestellt werden. Eine einem konkreten [Vorgang](#vorgang) beigefügte Datei wird als [Anlage](#anlage) geführt. |
| <a id="anlage"></a>Anlage | [Datei](#datei), die zu einem konkreten [Vorgang](#vorgang) gehört, zum Beispiel ein im [Formular](#formular) hochgeladener Nachweis oder ein während der Bearbeitung erzeugtes PDF. Die Zuordnung zeigt, zu welchem Fall der Inhalt gehört. Zusammengehörige Anlagen können in einem [Anlagensatz](#anlagensatz) gesammelt werden. |
| <a id="anlagensatz"></a>Anlagensatz | Benannte Sammlung von [Anlagen](#anlage) innerhalb eines [Vorgangs](#vorgang), zum Beispiel „Nachweise“ oder „Erstellte Dokumente“. [Aufgaben](#aufgabe) können gezielt mit einer solchen Sammlung arbeiten, etwa ihre Inhalte an ein [Fachsystem](#fachsystem) weitergeben. Der Name beschreibt den fachlichen Zusammenhang der enthaltenen [Dateien](#datei). |
| <a id="anbindung"></a>Anbindung | Konfigurierte Einbindung eines Dienstes, Speichers oder [Fachsystems](#fachsystem) in [Prosuna](#prosuna). Darüber lassen sich beispielsweise Daten austauschen, Nachrichten senden, [Dateien](#datei) speichern oder Zahlungen abwickeln. Die Einbindung wird mit den für die jeweilige [Instanz](#instanz) passenden Einstellungen eingerichtet und kann auch einen lokalen Speicher betreffen. Die Unterstützung weiterer Dienste kann durch [Erweiterungen](#erweiterung) ergänzt werden. |
| <a id="fachsystem"></a>Fachsystem | Externes Programm für ein spezialisiertes Fachgebiet, zum Beispiel Buchhaltung, Personalverwaltung oder eine branchenspezifische Fallbearbeitung. [Prosuna](#prosuna) kann über eine [Anbindung](#anbindung) Daten mit einem solchen System austauschen und es in einen übergreifenden [Prozess](#prozess) einbeziehen. |
| <a id="identitaetsanbieter"></a>Identitätsanbieter | Angebundener Dienst, über den sich [Beteiligte](#beteiligte) anmelden und Angaben zu ihrer Person oder [Organisation](#organisation) bereitstellen können, zum Beispiel über ein Servicekonto oder einen Unternehmenszugang. [Prosuna](#prosuna) kann diese Angaben als [Identität](#identitaet) in einem [Vorgang](#vorgang) verwenden. |
| <a id="erweiterung"></a>Erweiterung | Softwarepaket, das [Prosuna](#prosuna) zusätzliche Funktionen oder neue Arten von [Anbindungen](#anbindung) bereitstellt. Eine Erweiterung kann beispielsweise die Unterstützung für einen weiteren externen Dienst ergänzen. Für die Nutzung des Dienstes wird eine passende [Anbindung](#anbindung) eingerichtet. |

## Gestaltung und Wiederverwendung

| Begriff | Bedeutung |
| --- | --- |
| <a id="erscheinungsbild"></a>Erscheinungsbild | Gespeicherte Vorgaben für die Gestaltung von [Formularen](#formular) und der [Ansicht für Beteiligte](#ansicht-fuer-beteiligte), etwa Logo, Farben und Schriftgestaltung einer [Organisation](#organisation). Damit lassen sich die extern sichtbaren Angebote einheitlich gestalten, ohne den fachlichen Ablauf eines [Prozesses](#prozess) zu ändern. |
| <a id="vorlage"></a>Vorlage | **Zielbild:** Versionierte, intern in der eigenen [Instanz](#instanz) verfügbare Vorgabe zur Wiederverwendung. Eine Vorlage kann ein einzelnes [Formularelement](#formularelement), eine Gruppe von [Formularelementen](#formularelement), [Prozesselemente](#prozesselement) samt Konfiguration oder eine gesamte [Prozessdefinition](#prozessdefinition) enthalten. |
| <a id="baustein"></a>Baustein | **Zielbild:** Versionierter, wiederverwendbarer Inhalt, der über den [Marktplatz](#marktplatz) bereitgestellt oder von dort bezogen wird. Wie eine [Vorlage](#vorlage) kann ein Baustein einzelne [Formularelemente](#formularelement), Gruppen von [Formularelementen](#formularelement), [Prozesselemente](#prozesselement) samt Konfiguration oder eine gesamte [Prozessdefinition](#prozessdefinition) enthalten. |
| <a id="marktplatz"></a>Marktplatz | **Zielbild:** Angebot zum Bereitstellen und Beziehen von [Bausteinen](#baustein). Darüber können einzelne [Formularelemente](#formularelement), Gruppen von [Formularelementen](#formularelement), [Prozesselemente](#prozesselement) samt Konfiguration und gesamte [Prozessdefinitionen](#prozessdefinition) zwischen [Organisationen](#organisation) ausgetauscht und wiederverwendet werden. |

## Erproben und Änderungen nachvollziehen

| Begriff | Bedeutung |
| --- | --- |
| <a id="testmodus"></a>Testmodus | Möglichkeit, eine [Prozessversion](#prozessversion) probeweise auszuführen. Dabei kann auch ein gespeicherter Entwurf einer [Prozessversion](#prozessversion) erprobt werden. Die entstehenden Durchläufe heißen [Testvorgänge](#testvorgang) und werden einer [Testsitzung](#testsitzung) zugeordnet. |
| <a id="testvorgang"></a>Testvorgang | [Vorgang](#vorgang), der zur Erprobung im [Testmodus](#testmodus) gestartet wird. Er dient dazu, den vorgesehenen Ablauf mit konkreten Angaben durchzuspielen. Seine [Aufgaben](#aufgabe) und Ergebnisse gehören zur jeweiligen [Testsitzung](#testsitzung). |
| <a id="testsitzung"></a>Testsitzung | Rahmen für die Erprobung einer [Prozessversion](#prozessversion) mit zusammengehörigen [Testvorgängen](#testvorgang). So bleibt erkennbar, welche [Testvorgänge](#testvorgang) zu dieser Testsitzung gehören. Beim Beenden werden die dieser Sitzung zugeordneten [Testvorgänge](#testvorgang) gelöscht. |
| <a id="vorgangsverlauf"></a>Vorgangsverlauf | Chronologische Übersicht darüber, was bei der Bearbeitung eines einzelnen [Vorgangs](#vorgang) passiert ist. Sie zeigt [Aufgaben](#aufgabe), Ereignisse und Ergebnisse, zum Beispiel eine abgeschlossene Prüfung oder eine angeforderte Ergänzung. Damit lässt sich die Bearbeitung dieses konkreten Falls nachvollziehen. |
| <a id="aenderungsverlauf"></a>Änderungsverlauf | Aufzeichnung der Änderungen an der Gestaltung eines [Prozesses](#prozess), also an seiner [Prozessdefinition](#prozessdefinition) und den zugehörigen [Prozessversionen](#prozessversion). Sie hilft nachzuvollziehen, wie der Ablauf bearbeitet wurde. Was bei der Bearbeitung eines einzelnen Falls passiert ist, zeigt der [Vorgangsverlauf](#vorgangsverlauf). Weitere protokollierte Handlungen an verwalteten Objekten finden sich im [Audit-Log](#audit-log). |
| <a id="audit-log"></a>Audit-Log | Protokoll relevanter Handlungen an verwalteten Objekten einer [Instanz](#instanz), etwa dem Anlegen eines [Prozesses](#prozess) oder dem Ändern einer [Rolle](#rolle). Es hält unter anderem Handlung, handelnde Person oder System, betroffenes Objekt und Zeitpunkt fest. Der [Vorgangsverlauf](#vorgangsverlauf) beschreibt dagegen die Bearbeitung eines einzelnen Falls. |
